# Evaluation

Generated numbers live in [`RESULTS.md`](RESULTS.md) (`cargo run --release -p cfx-eval -- run --markdown docs/RESULTS.md`). This file covers the method.

## Corpora

| file | rows | what |
|---|---|---|
| `corpus/malicious.csv` | 25 | ClickFix command structures from public reporting (Proofpoint, ASEC, Sekoia, Unit 42, CloudSEK, ACSC, Fortinet, ANY.RUN, MITRE DET0340). Every row's `fidelity` is `reconstructed`; none is verbatim yet. Row ids have gaps because self-authored encoded rows were removed, so the corpus does not measure the deobfuscator. Each row records its target (Run dialog / Win+X / terminal) and origin. |
| `corpus/benign_fp_generators.csv` | 30 | The source false-positive table: pattern, signal it trips, exclusion condition, `bypass_risk`. |
| `corpus/benign.csv` | 400 | B001–B030 are one concrete instance per FP-generator row (same `bypass_risk`). The rest come from the install docs of ~60 tools, everyday dev/SRE/IT commands, Windows admin, Run-dialog shortcuts, secrets and blobs, prose, and multi-line terminal output and config. Each row has a realistic origin. |

Both are regenerated by `scripts/build_*_corpus.py`. Add your own history with `scripts/import_history.py`; its output stays local.

**Origin policy in the benign corpus.** Commands copied from a tool's own docs are `browser_vendor_docs`. Commands copied from blogs, StackOverflow or GitHub READMEs are `browser_unknown`. That is the harsher, realistic case: by policy those pages are never classified.

## Metrics

- **Detection rate**: malicious rows scoring Warn or higher on the fast path.
- **False-positive rate**: benign rows scoring Warn or higher. False blocks are reported separately.
- **Ablations**: without the allowlist, without deobfuscation, and without context. The last one approximates typed commands and Signal 2.
- **Per-feature contribution**: hits and summed weight on each corpus, and how often each feature was dampened on benign rows. A feature that fires on benign more than on malicious needs rework.
- **Latency**: fast path over every row, N iterations, after a warm-up pass; p50/p95/p99/max and the count over 5 ms.
- **Allowlist regression** (`crates/cfx-eval/tests/regression.rs`, also printed by the CLI): no malicious row's verdict may drop when the allowlist is on, both in its recorded context and in an attacker-best-case context (terminal target, engineer victim). If this fails, an entry is too broad.
- **Required negatives** (`regression.rs`): Chocolatey, Homebrew, `kubectl … | base64 -d`, a JWT and `certutil -hashfile` must stay Clean.

## Evasion testing

*Author-owned section.* Put variant corpora in `corpus/evasion/` (same columns as `malicious.csv`) and run:

```sh
cargo run --release -p cfx-eval -- run --malicious corpus/evasion/<file>.csv
```

The `no_deobfuscation` row of that output gives the before/after-deobfuscation comparison. `cfx-eval explain --deep '<cmd>'` shows which decode layer resolved what and whether the fast path handed off to Signal 3.
